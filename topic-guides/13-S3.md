## Amazon S3
**Why it exists**
S3 is object storage: you put a whole object in, you get a whole object out, and you address it by key. It gives up the things a filesystem offers — partial writes, renames, directory semantics — and in exchange gets effectively unlimited capacity, eleven-nines durability, and very low cost. Almost every AWS architecture uses it somewhere.
**Fundamentals**
- **Bucket** = the container. Bucket names are **globally unique** across all of AWS.
- **Object** = the data plus metadata, addressed by key. Max object size **5 TB**; a single `PUT` is capped at **5 GB**.
- **Everything is private by default** — buckets and objects.
- “Folders” are a console illusion; keys just contain slashes. Prefix filtering works on the key string.
**Strong read-after-write consistency** since December 2020, for PUT, DELETE, and LIST, in all Regions, at no extra cost.  Any answer that adds retries or sleeps to work around S3 consistency is wrong.
**Storage classes**
The organising idea: you pay less per GB for storage in exchange for paying more (in money or time) to retrieve it.
| Class | Trade |
| --- | --- |
| **Standard** | Frequent access, no retrieval fee |
| **Intelligent-Tiering** | AWS moves objects between tiers automatically based on observed access; use when the pattern is unknown or changing |
| **Standard-IA** | Cheaper storage, retrieval fee, still millisecond access |
| **One Zone-IA** | Same but a single AZ — cheaper, less durable. Fine for reproducible data |
| **Glacier Instant Retrieval** | Archive pricing with millisecond retrieval |
| **Glacier Flexible Retrieval** | Minutes to hours to retrieve |
| **Glacier Deep Archive** | Cheapest, \~12 hours to retrieve. Long-term compliance archive |
**Core features**
**Versioning** — keeps every version of an object. A delete becomes a *delete marker*, so nothing is really gone. This is the answer to accidental deletion and overwrite protection, and it is a **prerequisite for Object Lock and replication**.
When you enable versioning on a bucket that already contains objects:
- Existing objects automatically get the version ID **null**.
- They do **not** receive a new unique version ID.
- When an existing object is overwritten, the new object gets a **unique version ID**, and the old object keeps the **null** version ID.
**Lifecycle rules** — automatically transition objects between classes and expire them on a schedule. This is what *acts*; S3 Analytics only *recommends*.
Lifecycle rules = Automatic storage class transitions + expiration. Example: Move objects from **S3 Standard → S3 Standard-IA → S3 Glacier** as they become older.
**Lifecycle rules **Expiration actions:Automatically delete objects or old object versions from an S3 bucket after a specified time to reduce storage costs
Also we can automate deleting unfinished upload stale data using **Lifecycle rules**
**Replication (CRR / SRR)** — asynchronous copying to another bucket, cross-Region or same-Region. Requires versioning on both buckets.
**Static website hosting** — serve a bucket as a website.
**Event notifications** — see below.
**Server-side encryption** — SSE-S3, SSE-KMS, SSE-C, and client-side encryption are covered in full under **S3 Encryption in Part 4**, next to KMS, because the four options only make sense once you understand envelope encryption.
**Presigned URLs **(Query String Authentication)
A presigned URL grants time-limited access to a private object, without the recipient needing AWS credentials.
The mechanism explains both of its gotchas: **the URL is signed with the credentials of whoever generated it, and carries exactly that principal’s permissions.**
- Therefore a presigned URL can accidentally grant *more* than intended if the signer’s role is broad.
- Therefore the URL **cannot outlive the credentials that signed it**. Signed with IAM user credentials, it can last up to **7 days**. Signed inside a Lambda function (which uses a role’s temporary credentials), it stops working when those credentials expire — often 1 hour, at most 12. This surprises people constantly, in production and on the exam.
Uses: temporary download links, and letting a browser **upload directly to S3** (presigned `PUT`, or a presigned POST) so the file never passes through your servers.
**Multipart upload**
A single `PUT` is limited to **5 GB**, and a single-stream upload of a large file is slow and fragile — one network blip restarts everything.
Multipart splits the object into parts that upload in parallel and can be retried individually.
- **Recommended above 100 MB, required above 5 GB.**
- Part size minimum 5 MB (except the last part), maximum **10,000 parts**, maximum object 5 TB.
- **Incomplete multipart uploads keep costing money** — the uploaded parts sit in the bucket, invisible in the object listing. Add a lifecycle rule with `AbortIncompleteMultipartUpload`. This is the answer to “unexplained S3 storage cost”.
- **Transfer Acceleration** routes uploads through CloudFront edge locations, which helps most over long distances. Combines with multipart.
- **Byte-range fetches** do the same trick in reverse: parallelise a download, or fetch just the first bytes of a file to read a header.
**S3 event notifications**
```plain text
Object created / removed / restored / replicated
        ↓
SQS  |  SNS  |  Lambda  |  EventBridge
```
- Event types: `s3:ObjectCreated:*`, `s3:ObjectRemoved:*`, `s3:ObjectRestore:*`, `s3:Replication:*`.
- **Native filtering is prefix and suffix only.** If the question needs richer filtering, or many targets, or replay — route to **EventBridge** instead, which unlocks all of that.
- Delivery is **at least once**, so consumers must be idempotent.
- The destination needs a **resource policy** allowing `s3.amazonaws.com` to publish. Missing that policy is why a notification silently never fires.
**S3 Server Access Logging** records requests made to a bucket and stores the logs as objects.
So:
> **No new files + bucket size increased → access log files are being stored.**
**S3 Select vs Athena**
**S3 Select** runs SQL against **one object** (CSV, JSON, Parquet, optionally compressed) and returns only matching rows and columns. It saves bandwidth and cost versus downloading the whole file.
**Athena** runs SQL across **many objects / a whole dataset**, with a catalog and joins.
The dividing line is the number of objects.
**S3 Analytics (Storage Class Analysis)**
Observes access patterns and **recommends** when objects should move from Standard to Standard-IA. It generates a report; it **does not move anything**. You act on it with a lifecycle rule.
- **Need recommendations** → S3 Analytics
- **Need automatic transitions on a schedule** → Lifecycle
- **Need automatic tier movement based on actual access** → Intelligent-Tiering
**S3 Object Lock**
**WORM** — Write Once, Read Many. Prevents an object version from being deleted or overwritten for a period, or indefinitely.
- **Requires versioning**, because it protects specific *object versions*.
- Must be enabled **at bucket creation**.
- **Retention period** — locked until a date. **Legal hold** — locked until manually removed, no expiry.
- **Governance mode** — users with a special permission can bypass it. **Compliance mode** — nobody can, including the root user, until retention expires.
Uses: regulatory compliance, immutable backups, ransomware protection.
**The S3 feature map**
| Feature | Purpose |
| --- | --- |
| **Object Lock** | Prevent deletion/overwrite (WORM) |
| **Versioning** | Keep previous versions for recovery |
| **Lifecycle** | Automatically transition or delete objects |
| **Glacier Vault Lock** | Compliance controls for Glacier vaults |
| **Replication (CRR/SRR)** | Copy objects to another bucket |
| **Encryption** | Protect data at rest |
| **Bucket Policy** | Bucket-level access control |
| **Access Points** | Separate named endpoints with their own policies on a shared bucket |
| **Intelligent-Tiering** | Automatic tier movement based on access |
| **Analytics** | Recommend storage optimisation |
| **Presigned URL** | Temporary access to a private object |
| **Event Notifications** | Trigger Lambda/SQS/SNS/EventBridge on changes |
| **Transfer Acceleration** | Faster long-distance uploads via edge locations |
| **S3 Select** | Retrieves only the required rows and columns from an S3 object using SQL expressions instead of downloading the entire file. |
| S3 Range Fetch | Retrieves only a specific byte range of an S3 object instead of downloading the complete object. |
An **S3 Access Point** is a **separate entry point to an S3 bucket** with its own permissions and configuration. One bucket can have multiple access points.
Think:
```plain text
                    S3 Bucket
                       │
          ┌────────────┼────────────┐
          ↓            ↓            ↓
      Access Point  Access Point  Access Point
        App A          App B        App C
```
Instead of giving every application one huge bucket policy, each application can use its **own access point with its own policy**.
**Example**
You have:
```plain text
my-company-bucket
├── photos/
├── invoices/
└── reports/
```
You could create:
```plain text
Photos App → PhotosAccessPoint → photos/*
Finance App → FinanceAccessPoint → invoices/*
Reports App → ReportsAccessPoint → reports/*
```
### S3 Replication
**Types**
- **SRR** → Same Region
- **CRR** → Different Regions
**Replication can target**
- Whole bucket
- Prefix
- Object tags
**Important**
- Objects + metadata/tags → **can be replicated**
- **Lifecycle actions → NOT replicated**
- Enabling replication → **new objects**
- Existing objects → use **S3 Batch Replication**
| Requirement | CRR | SRR |
| --- | --- | --- |
| Source versioning | ✅ Required | ✅ Required |
| Destination versioning | ✅ Required | ✅ Required |
| IAM permissions | ✅ Required | ✅ Required |
| Different Region | ✅ Yes | ❌ No |
**S3 replication uses an IAM role** that gives the S3 service permission to:
- Read objects/version information from the **source bucket**
- Replicate/write those objects to the **destination bucket**
Simple flow:
```plain text
Source S3
   ↓
S3 assumes IAM replication role
   ↓
Destination S3
```
**Exam memory**
> **Replication = objects, not lifecycle rules.**
  **Old objects = Batch Replication.**
### S3 Object Lambda
**What it is**
S3 Object Lambda lets you use **Lambda to modify an S3 object when someone requests it**, before the object is returned.
**Mental model**
```plain text
User
 ↓ GET object
S3 Object Lambda Access Point
 ↓
Lambda
 ↓ transform
Modified object
 ↓
User
```
**Example**
S3 contains:
```plain text
photo.jpg
```
User requests the photo:
```plain text
GET photo.jpg
      ↓
Lambda
      ↓
resize / watermark
      ↓
User gets resized photo
```
The **original ****`photo.jpg`**** in S3 is not changed**.
**Common uses**
- Resize images
- Add watermarks
- Filter data
- Redact sensitive information
- Change data format
- Compress/decompress objects
**Important**
It works with:
- `GET`
- `LIST`
- `HEAD`
The Lambda function processes the result before returning it.
**Don't confuse**
```plain text
S3 Event + Lambda
UPLOAD → S3 event → Lambda
```
Means:
> **Something was uploaded → process it**
```plain text
S3 Object Lambda
GET → Object Lambda → Lambda → modified object
```
⚠️ **Current AWS note:** S3 Object Lambda availability changed on November 7, 2025; AWS says it is now limited to existing customers already using it and select APN partners.
### S3 CORS → OPTIONS Preflight Request
**Mental model**
**OPTIONS = browser preflight check.**
Before a cross-origin request like `PUT` or `DELETE`, the browser asks:
> “Am I allowed to send this request?”
S3 checks the **CORS configuration** and responds.
**Example**

```plain text
OPTIONS → Check permission
PUT     → Actual request
```
`MaxAgeSeconds`
Controls how long the browser caches the **OPTIONS response**.
`3600` = **1 hour**
**Recall check — S3**
- **Store files, images, backups** → S3
- **S3 CORS → OPTIONS = preflight check**
- **Static website hosting** → S3
- **Archive data** → Glacier classes
- **Unknown or changing access pattern** → Intelligent-Tiering
- **Accidental deletion protection** → Versioning
- **Automatically move old objects** → Lifecycle
- **Replicate to another Region** → CRR
- **Upload triggers processing** → S3 event notification → Lambda/SQS/SNS
- **Complex event filtering or many targets** → send S3 events to EventBridge
- **Native S3 notification filtering** → prefix and suffix only
- **Notification never fires** → destination resource policy missing
- **Temporary download link for a private object** → presigned URL
- **Let a user upload directly to S3 without credentials** → presigned URL / presigned POST
- **Presigned URL expires too early** → signed with a role’s temporary credentials
- **Upload a file larger than 5 GB** → multipart upload (required)
- **Speed up large uploads** → multipart + Transfer Acceleration
- **Unexplained S3 storage cost** → incomplete multipart uploads; add an abort lifecycle rule
- **Download only part of a file** → byte-range fetch
- **SQL on a single object** → S3 Select
- **SQL across a whole dataset** → Athena
- **Recommendations only, no action** → S3 Analytics
- **Immutable / WORM / ransomware protection** → Object Lock (requires versioning)
- **Nobody, not even root, can delete until expiry** → Object Lock compliance mode
- **Read immediately after write** → strongly consistent, always
- **Max object size** → 5 TB; single PUT 5 GB
- **“Modify/transform S3 object when it is READ/GET” → **S3 Object Lambda
- **“Process object after upload” → **S3 Event Notification + Lambda
- **CORS** → controls whether web applications from different origins can access S3. It has nothing to do with ownership.
- **S3 Object Ownership** makes the **bucket owner automatically own all objects in the bucket**, regardless of which AWS account uploaded them.
